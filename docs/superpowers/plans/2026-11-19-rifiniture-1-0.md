# Rifiniture 1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eliminare i quattro difetti trovati nel test su telefono: barra nativa che copre l'app, tastiera e barra in basso, foglio "Aggiungi alimento", menu grigio delle scelte, e dare all'app un'icona moderna (vetro).

**Architecture:** Logica pura in file piccoli e testati (`src/keyboard.js`), DOM nei file `ui/` (come il resto dell'app), stili in `src/styles/input.css` compilati in `app.css`. Le `<select>` diventano gruppi di `<input type="radio">` veri, quindi `FormData` e validazione non cambiano. L'icona nasce da un solo disegno SVG in `scripts/make-icons.mjs` che produce sfondo, primo piano e icone complete.

**Tech Stack:** HTML, JavaScript ES (moduli nativi), Tailwind 3.4 (CLI), `node:test`, `sharp` (icone), Capacitor 8 / Android (Gradle 8.14, JDK 21).

**Spec:** `docs/superpowers/specs/2026-11-19-rifiniture-1-0-design.md`

## Global Constraints

- Testi dell'interfaccia e commenti nel codice in italiano; funzioni `camelCase`, costanti `UPPER_SNAKE`, id HTML `kebab-case`; una costante condivisa si definisce una sola volta in `src/config.js`.
- Nessuna dipendenza nuova; niente plugin `@capacitor/keyboard`. L'app deve restare identica nel browser e nella PWA (nessuna logica solo-Android nell'interfaccia) e funzionare offline.
- Tailwind genera solo le classi scritte per intero in `index.html` e `src/**/*.js`: mai classi costruite a pezzi. Dopo ogni cambio di classi o di `src/styles/input.css`: `npm run build:css` (`app.css` è generato, non si modifica a mano).
- Nelle `<dialog>` mai `flex`/`grid` da soli (rompono la chiusura): solo `open:flex open:flex-col`.
- `sw.js`: `VERSION = 'v16'` e ogni nuovo modulo di `src/` nel `PRECACHE` (un test lo pretende).
- Icone: ogni pixel non trasparente del primo piano Android dentro il cerchio di 72 dp (raggio 144 px a xxxhdpi), nessuna ombra fuori dalla lastra; palette dell'app `#A7A0F0` → `#7AA2F7` → `#7DC8F0`.
- Nessun commit finché l'utente non lo chiede (le modifiche restano nel working tree); niente sotto-agenti.
- Ambiente (PowerShell): `$env:PATH = "$env:APPDATA\fnm\node-versions\v26.13.1\installation;$env:PATH"` prima di `node`/`npm`. Il worktree non ha `node_modules`: collegarlo con `New-Item -ItemType Junction -Path node_modules -Target C:\Users\matti\Code_Project\Webapp_Fitkia\node_modules` e toglierlo a fine lavoro con `cmd /c rmdir node_modules`. Per Gradle: `JAVA_HOME=C:\Users\matti\.jdks\jbr-21.0.11`.

## Review Focus

1. Tastiera chiusa con il pulsante "v" mentre il campo resta attivo: la barra in basso deve tornare (test su `readKeyboard`, Task 2).
2. Rotazione o cambio di larghezza con la tastiera chiusa: la misura di riferimento si ricalcola e la barra non resta nascosta (test, Task 2).
3. Passare da un campo di testo a un altro (la tastiera resta aperta): la barra non deve riapparire nel mezzo (test: la misura di riferimento non scende mai con la stessa larghezza, Task 2).
4. Nomi e descrizioni con `<`, `&`, `"`: devono uscire neutralizzati; ritmo con id numerici (`0.25`) deve selezionarsi (test su `choiceMarkup`, Task 4).
5. Onboarding inviato senza aver scelto il sesso: errore sotto il gruppo e focus sulla prima scelta; nessuna `<select>` rimasta e nessuna `<dialog>` con `flex` da solo (test statici su `index.html`, Task 3 e 4).
